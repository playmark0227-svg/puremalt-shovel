# ピュアモルト チタンスコップ LP — 運用ガイド

チタニウム製スコップ（剣先／角）を販売する、ランディングページと購入導線一式です。
購入の流れは **LP → 商品詳細 → ご注文内容の確認 → Stripe決済画面 → 購入完了** です。

- HTML / CSS / JavaScript だけで作られた静的サイトです。ビルド作業・サーバー・データベースは不要です。
- 商品名・価格・送料・販売条件・事業者情報は、**`assets/js/config.js` の1ファイルにまとめてあります**。ここを書き換えれば全ページに反映されます。
- 現在の価格・スペック・販売条件は **仮の値（【仮】）** で、事業者情報は **未入力（【要入力】）** です。公開前に必ず確定させてください（→「5. 仮の値・要入力項目の一覧」）。
- 掲載している商品画像は、すべて **AIで生成したイメージ画像** です（→「9. 画像について」）。

## 2. プレビュー（手元での表示確認）

- **いちばん簡単な方法**：`index.html` をダブルクリックしてブラウザで開きます。この方法（file://）でも、すべてのページが動作するように作ってあります。
- **サーバー経由で確認したい場合**（公開時の状態に近い確認）：ターミナルで LP フォルダに移動し、次を実行してから `http://localhost:8000/` を開きます。

  ```sh
  python3 -m http.server 8000
  ```

- file:// で開いた場合、ブラウザによってはモデル切り替え時にアドレスバーの `?model=` が更新されないことがあります。画面の表示は正しく切り替わるので問題ありません。
- Stripe の決済後に thanks.html へ戻る動作は、公開した https のURLでしか確認できません（file:// のページは Stripe の戻り先に指定できないため）。
- フォント（Shippori Mincho・Noto Sans JP・Cormorant Garamond）は Google Fonts から読み込んでいます。オフラインの場合は、パソコンに入っている代わりのフォントで表示されます。

## 3. config.js の編集方法

`assets/js/config.js` をテキストエディタ（VS Code、メモ帳、テキストエディットの「標準テキスト」など）で開いて編集し、保存後にブラウザを再読み込みします。

**注意点**

- 書き換えるのは `'…'`（シングルクォート）で囲まれた部分だけです。
- 価格（`price`）と送料（`fee`）は **税込の金額を半角数字だけ** で入力します（カンマ・円記号なし）。例：`39800`
  → サイト上では自動的に「¥39,800（税込）」と表示されます。
- 行末のカンマ `,` や、括弧 `{ } [ ]` を消さないでください。1文字でも崩れるとページの価格や情報が表示されなくなります。
- 文章の中でシングルクォート `'` を使いたいときは、全角の「’」を使ってください。
- `// 【仮】` は「仮の値」という目印のコメントです。値を確定したらコメントは消してかまいません。

**主な設定項目**

| 項目 | 場所 | 内容 |
|---|---|---|
| ブランド名・キャッチコピー | `brand.name` / `brand.nameJa` / `brand.tagline` | サイト名とキャッチコピー |
| 公開URL | `brand.siteUrl` | 公開時に入力（例：`https://example.com`）。**現在は控え用で、ページには自動反映されません**（OGP画像のURLは index.html を手作業で修正 → 8） |
| 送料 | `shipping.fee` / `shipping.label` / `shipping.note` | 送料（税込・円）、表示文言、注記 |
| 最大数量 | `maxQuantity` | 1回のご注文で購入できる最大数量（特商法表記「販売数量の制限」とご注文内容の確認に表示）。Stripe の数量調整の最大値と同じにします |
| 商品（剣先） | `products.kensaki` | 商品名・価格・キャッチ・説明・用途・スペック・決済リンク |
| 商品（角） | `products.kaku` | 同上 |
| 共通スペック | `commonSpecs` | 素材・グリップ・柄の形状（両モデル共通） |
| 事業者情報 | `seller` | 特商法表記・フッター・完了画面などに表示 |
| 販売条件 | `policies` | 支払方法・支払時期・発送時期・返品・不良品・キャンセル・その他費用 |

- 商品の表示順は `productOrder`（`['kensaki', 'kaku']`）で決まります。
- `products.〇〇.id` と `productOrder` の値（`kensaki` / `kaku`）は、URL（`?model=kensaki`）やStripeの戻り先URLにも使っているため **変更しないでください**。
- 画像のファイル名を変える場合は、`images` と `commonImages` のパスもあわせて変更してください。

## 4. 購入ボタンの動き（デモモード）

各商品の `stripePaymentLink` が **空欄（`''`）の間は「デモモード」** で動きます。

| 状態 | 「Stripeの決済画面へ進む」を押したとき |
|---|---|
| 決済リンクが空欄（現在） | 実際の決済は行われず、`thanks.html?demo=1&model=（モデル）` へ移動します。完了画面の見出しは「デモ：購入完了画面の表示確認」になり、「Stripeの決済リンクが未設定のため、実際の決済・注文は行われていません」という案内が目立つ形で表示されます。ご注文内容の確認画面にもデモである旨が表示されます。 |
| 決済リンクを設定済み | そのモデルの Stripe 決済画面（`https://buy.stripe.com/…`）へ移動します。支払い後は、Stripe 側で設定した戻り先（thanks.html）に戻ります。 |

- 決済リンクはモデルごとに判定されます。片方だけ設定した場合、未設定のモデルはデモモードのままです。
- thanks.html は「表示」のためのページで、支払いの成否を確認する機能はありません（サーバーがないため）。**注文の確認と発送は、必ず Stripe ダッシュボードの支払い一覧と支払い通知メールで行ってください。** 支払い後に通信が切れるなどして、お客様が thanks.html に戻らないこともあります。

**事業者名・所在地・電話番号の書き方**

1. **販売事業者名**：法人は登記上の名称と所在地を表示します。個人の場合は氏名（戸籍上の氏名または商業登記した商号）を表示し、**屋号やサイト名だけの表示は不可** です。
2. **所在地・電話番号を省略する方法**：個人事業主に限り、所在地・電話番号を「請求があった場合には速やかに開示いたします」と表示する方法もあります（請求があれば遅滞なく開示する必要があります）。ただし **コンビニ決済を使う場合は不可** です（固定電話番号（050可）と完全な表記が必要）。
3. **電話番号**：確実につながる番号を記載してください。

- 特商法表記・プライバシーポリシーの本文は、公開前に専門家（弁護士・行政書士など）の確認を受けることをおすすめします。
- プライバシーポリシーの制定日は「2026年9月15日」になっています。公開日に合わせて privacy.html を修正してください。

## 6. Stripe 決済リンク（Payment Links）の設定

モデルごとに1本ずつ、合計2本の決済リンクを作成します（剣先用・角用）。
以下の画面名は Stripe 公式ドキュメント（2026年9月時点）に記載の名称です。実際のダッシュボードの表記と多少異なる場合があります。

### 6-1. まずテスト環境（サンドボックス）で作る

1. **テスト環境に切り替え**：Stripe にログインし、アカウント選択から「サンドボックス」に切り替えます。サンドボックスでは実際の決済は発生せず、テスト用カードだけが使えます。
2. **公開情報**：設定 →「公開情報」で、サポート用のメールアドレス・電話番号・WebサイトURL、プライバシーポリシーのURL（privacy.html の公開URL）を登録します。
3. **特商法表記の登録**：設定 →「ビジネス」→「編集」を開き、ページ下部の「商取引に関する開示」に tokushoho.html の公開URLを登録します（→「7. Stripe と特定商取引法の表記」）。
4. **決済画面のポリシー表示**：設定 →「Checkout と Payment Links」で「連絡先情報」と「リーガルポリシー」を有効にします。「返品および返金に関するポリシー」には、サイトと同じ返品条件（返品の可否・期間・返送料の負担）を設定します。
   - **領収メールをオンにする**：設定 →「カスタマーメール」で「支払い成功」（領収書メール）をオンにします（**本番環境でも必ず設定**）。thanks.html では「Stripeから領収メールが届く」と案内しているため、オフのままだと案内と食い違います。
5. **決済手段**：設定 →「決済手段」で使う決済手段を有効にします（現在のサイト表記：カード、Apple Pay、Google Pay）。
   - 銀行振込は Payment Links では使えません。
   - コンビニ決済には別途審査があり、固定電話番号（050も可、携帯は不可）と営業時間の掲載、完全な特商法表記などが必要です。創業3年未満の個人事業主は利用できません。
   - コンビニ決済・PayPay などを追加した場合は、`policies.paymentMethods` の文言も変更してください。
6. **送料の作成**：「配送料」画面で「配送料を作成」を押し、金額（税込）・表示名・配達予定日を入力して保存します。
   - 現在の設定（送料無料）なら、金額 0 円、表示名「全国送料無料」とします。
   - 配達予定日は `policies.deliveryTiming`（現在：5営業日以内に発送）と矛盾しない内容にします。
   - 送料は1回の注文につき定額で、数量によって変えることはできません。
7. **リンク作成を開始**：「Payment Links」→「＋新規」→「＋新しい商品を追加」を押します。
8. **商品情報**：
   - 商品名はモデル名まで入れます（例：「ピュアモルト チタンスコップ 剣先」。config.js の `name` と同じにすると確実です）。
   - 説明欄には、税込であること、送料の金額、「ウイスキー・酒類は含まれません。お届けするのはスコップ本体のみです。」の旨を書きます。
   - 画像を登録し、価格は **日本円（JPY）・1回限りの支払い** で、**税込の総額**（剣先 39,800円／角 42,800円 ※仮）を入力して「商品を追加」を押します。
   - Stripe Tax を使う場合は、税金処理を「内税」にします（「自動」でも日本円は内税になります）。
9. **数量調整を許可**：「決済ページ」→「商品」で「顧客が数量を調整できるようにする」をオンにし、最小 1・最大は config.js の `maxQuantity`（現在 10【仮】）と **同じ数** を設定します。
   - URL で数量を指定する機能はないため、サイトの確認画面では「数量はStripeのお支払い画面で最大10点まで変更できます」と案内し、特商法表記の「販売数量の制限」にも「1回のご注文につき最大10点まで」と表示しています（どちらも `maxQuantity` から表示）。
   - 最大値を変えるときは、Stripe と `maxQuantity` の両方を変更してください。
10. **配送先住所の収集（日本のみ）**：「オプション」→「顧客の住所を徴収する」→「請求先住所と配送先住所」を選び、配送先の国は「日本」だけを選択します。続けて手順6で作った送料を追加します。配送に電話番号が必要な場合は「顧客に電話番号の提供を求める」もオンにします。
11. **支払い後に自サイトへ戻す**：「支払い後」タブで「確認ページを表示しない」（自社サイトへリダイレクト）を選び、次のURLを入力します（`（公開ドメイン）` は実際のドメインに置き換え）。
    - 剣先のリンク：`https://（公開ドメイン）/thanks.html?model=kensaki&session_id={CHECKOUT_SESSION_ID}`
    - 角のリンク：`https://（公開ドメイン）/thanks.html?model=kaku&session_id={CHECKOUT_SESSION_ID}`
    - `{CHECKOUT_SESSION_ID}` はそのまま入力します（Stripe が自動で置き換えます）。サイトをサブフォルダに置く場合は、パスも含めてください。
12. **リンクを発行して貼り付け**：「リンクを作成」を押し、発行されたURLを `assets/js/config.js` の該当モデルに貼り付けます。テスト環境のURLは通常 `https://buy.stripe.com/test_…` の形式です。

    ```js
    kensaki: {
      …
      stripePaymentLink: 'https://buy.stripe.com/test_xxxxxxxx',
    ```

    同じ手順で「角」のリンクも作成し、`products.kaku.stripePaymentLink` に貼り付けます。
13. **テスト購入**：公開したサイトから購入ボタン → Stripe 決済画面へ進み、テスト用カードで支払います。
    - Visa：`4242 4242 4242 4242`（有効期限は未来の任意の日付、セキュリティコードは任意の3桁）
    - JCB：`3566 0020 2036 0505`
    - `thanks.html?model=…` に戻ること、ダッシュボードの支払い詳細に配送先住所が記録されることを確認します。
    - サンドボックスでは、顧客への領収書メールは既定では送信されません。本番環境では手順4の「カスタマーメール」設定で領収メールが送信されることを確認してください。

### 6-2. 本番環境（ライブ）に切り替える

14. 本番利用に必要なアカウント設定（事業情報など）を完了し、アカウント選択でサンドボックスを抜けて本番環境に切り替えます。

    - 差し替え後に、テスト用のリンク（`test_` を含むURL）が残っていないか確認してください。

### 6-3. 運用（注文の確認と発送）

15. 注文は、ダッシュボードの支払い一覧と支払い通知メールで確認して発送します（サーバーなしの手動運用）。

    - コンビニ決済を有効にした場合は支払いが後日確定するため、支払い成功を確認してから発送してください。

## 7. Stripe と特定商取引法の表記

- 特定商取引法により、通信販売を行う事業者は「特定商取引法に基づく表記」の掲載が必要です。
- Stripe のサポート記事では、Stripe で決済を受ける事業者は（割賦販売法の観点から）特商法の対象外の取引であっても、事業者情報の開示ページをWebサイトに掲載する必要があるとされています。
- このページは **トップページと決済関連ページから到達できること** が求められます。本サイトでは、全ページのフッターと purchase.html（ご注文内容の確認）に tokushoho.html へのリンクを置いています。
- Stripe ダッシュボードの「商取引に関する開示」に tokushoho.html の公開URLを登録すると（→ 6-1 手順3）、Stripe 決済画面の下部にもリンクが表示されます。
- 表記の内容が不完全だったり、サイトと Stripe で内容が食い違っていたりすると、コンビニ決済などの審査で否認される理由になります。**`seller` の【要入力】をすべて埋めてから** 登録してください。

## 9. 画像について

- `assets/img/` の商品画像（hero / kensaki-studio / kaku-studio / scene-kensaki / scene-kaku / grip-cork / titanium-detail）は、すべて **AIで生成したイメージ画像** です。実際の商品の形状・色・質感とは異なります。
- そのため、商品画像の近くに「※画像はイメージです。実際の商品とは異なる場合があります。」と表示しています。
- 実物の写真に差し替える場合は、**同じファイル名で上書き** すると HTML の変更は不要です。縦横比をそろえると、きれいに表示されます。

| ファイル | 縦横比 | 目安のサイズ |
|---|---|---|
| hero.jpg | 16:9（商品は画面の右半分に配置） | 2400×1339px |
| kensaki-studio.jpg / kaku-studio.jpg / grip-cork.jpg | 4:5（縦長） | 1208×1500px |
| scene-kensaki.jpg / scene-kaku.jpg / titanium-detail.jpg | 16:9 | 1920×1071px |

- 実物写真に差し替えた後も、実物と見え方が異なる可能性がある場合は、注記を残しておくことをおすすめします。
- 画像はファイルサイズを小さくしておくと、ページの表示が速くなります（1枚あたり数百KB程度が目安）。
